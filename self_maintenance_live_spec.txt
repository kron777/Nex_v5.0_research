2. HOW REANIMATION "UN-PAUSES" (what the code actually does)
------------------------------------------------------------
No trio code writes beliefs.paused = 0. The un-pause is functional, not a DB write:
  dormancy.py scan_incremental   SELECT ... FROM beliefs WHERE source IN
                                 ('fountain_insight','synergized','behavioural_observation')
                                 ORDER BY created_at ASC LIMIT 50   <- no paused filter
                                 -> dormant_beliefs
  consolidation._run_fast        wake_one(): highest dormancy_score with
                                 reanimated_at IS NULL                <- no paused filter
  generator (every 20th fire)    SELECT ... FROM beliefs WHERE id=?   <- no paused filter
                                 -> appended to that fire's retrieval result
So a belief the regulator paused can be injected straight into a fire. Retrieval
proper (retrieval.py) honours paused; the reanimation side door does not.
The only code that writes paused = 0 is the harmonizer (tier = 8, paused = 0 when it
resolves a contradiction). Its selections filter paused = 0, so it never picks a
regulator-paused belief, and tier 8 is outside the active set anyway.
State today: dormant_beliefs has 50 rows, all already reanimated, 0 pending. The
scan only ever looks at the 50 OLDEST beliefs of three sources, so the queue is
small and currently exhausted. The conflict is structurally real, practically idle.


3. WHERE THE REGULATOR AND THE TRIO WOULD FIGHT
-----------------------------------------------
(a) Selection overlap. The regulator pauses old, low-confidence tier-6 beliefs; the
    dormancy scan flags old, unreferenced beliefs. Same end of the graph.
(b) Side-door leak. Every 20th fire can re-inject a paused belief. Upper bound if
    EVERY reanimation hit a regulator-paused belief: ~1 per 20 fires (~36/day at
    ~2 min/fire) against ~550 pauses/day, i.e. <= ~7% leak. Realistic: far lower
    while the dormant queue is exhausted.
(c) If the governor is re-enabled (NEX5_GOVERNOR_OFF removed): cadence 5 in a trough
    (4x the leak), and the rut-mirror adds tier-6 'self_rut_notice' beliefs which the
    regulator would later pause — suppressing her own rut-mirror, the opposite of
    its purpose.
(d) No hunting. None of the three is a controller on the active-set size, so two
    loops never fight over one variable; the risks are leak and intent conflict.
    Second-order path: if pausing hurts quality, striking falls, readiness.pen bites,
    fires slow, inflow to A drops — a damping direction, but it is a guard metric.


4. RESOLUTION (all on the regulator side; the trio is not modified)
-------------------------------------------------------------------
R1  The regulator never pauses a belief that is in dormant_beliefs (any state).
    Leaves the reanimation pool alone; costs nothing (the pool is 50 rows).
R2  The regulator never pauses source 'self_rut_notice' (never mutes the mirror).
R3  Measure the remaining side-door leak instead of closing it: count reanimation
    injections of ledger-paused beliefs (generator logs "Reanimated dormant
    belief_id=%d"; join against the regulator's ledger).
    Pre-registered bound: leak <= 5% of ledger pauses, else stop.
R4  REJECTED: adding a paused filter to the reanimation path. That edits trio code.
NEX5_GOVERNOR_OFF stays as it is for the whole evaluation. Re-enabling the governor
is a separate variable and must not change during Phase B.
