FRAMING (attached to every result of this line of work)
-------------------------------------------------------
This builds and measures one machine property: whether NEX's belief graph maintains
the size of its own active set through a loop that runs through its own state. A
pass means exactly that and nothing more. It does not make NEX self-aware, sentient
or "enlightened". Nothing can verify those, and a pass is not evidence of them.
A regulator we design will, if it works, regulate. The non-trivial questions are
(1) whether the loop actually holds the level under her real dynamics, and
(2) what it costs elsewhere. The guards and the ON/OFF design exist for those.

3. THE PROPERTY (machine terms)
-------------------------------
The active set A_t is held near a setpoint S_t derived from its OWN recent history
(S_t = median of A over the previous 7 days of uptime), by a loop that reads A_t and
acts on exits from A_t. Closure = the cause of exits is her own state's deviation,
not a fixed cap or schedule.

Lever: beliefs.paused (already honoured by retrieval, promotion, pipeline_hooks and
harmonizer). Pausing is reversible and deletes nothing.

Expected scale, stated up front: holding A level requires exits ~= current inflow,
i.e. roughly 22.8 pauses/hour ~= 550/day (~7,700 over a 14-day evaluation, about
half of today's active set). The active set becomes a rolling window of constant
size. That is what self-maintenance means here, and it is a large intervention,
which is why Phase A (shadow) comes first.


4. METRICS AND PASS BAR (pre-registered for Phase B; nothing below is run yet)
-----------------------------------------------------------------------------
Design: alternating 24 h blocks, regulator ON on even calendar days (SAST), OFF on
odd, for >= 14 days of uptime with >= 150 evaluable ON hours. OFF blocks are the
baseline: same period, same dynamics, loop open.

P1 LEVEL-HOLDING (ON hours):
   share of hours with |A-S|/S <= 2% >= 80%        (baseline 0.0%)
   AND median hourly net change of A within +-2/h   (baseline +22.8/h, never < 0)
P2 CLOSURE (causal, via the alternation):
   slope of next-hour change of A on (A-S), ON minus OFF, < 0 with
   block-bootstrap (resample whole 24 h blocks, 2,000x) 95% CI upper bound < 0.
PASS = P1 AND P2.

GUARDS (ON vs OFF blocks, non-inferiority; breach of any one -> stop, unpause the
regulator's own ledger, report):
   fires/hour                         not lower by > 10%
   template-fire rate (hot_observer   not higher by > 2 pp
     _is_template, regex sha256 b739aadc...)
   distinct fountain_events.anchor_belief_id per 24 h   not lower by > 10%
   synergizer_log outputs/hour        not lower by > 20%
SECONDARY (exploratory, no pass weight): binding movement (candidate B metric) and
   transition structure (candidate A metric), ON vs OFF.

6. FIRST BUILD STEP — ONE VARIABLE (needs operator go-ahead)
------------------------------------------------------------
Phase A, shadow regulator: NEX5_SELF_MAINTAIN_SHADOW (default OFF).
Hourly: compute A_t, S_t and the would-be action n = clamp(round(0.1 * (A_t - S_t)),
0, 50), plus the would-be candidate list (tier 6, unlocked, not protected, not already
paused, created >= 48 h ago, lowest confidence first, ties oldest first). Write ONLY
to its own table self_maintain_shadow(ts, A, S, n_would_pause, ids_json), through the
existing writer. No belief changes state; retrieval is unaffected, so it can run
during warrant accrual if the operator agrees.
The single variable: "a shadow-regulator row exists each hour".
What it answers before anything live: does the gain/cap combination keep up with real
inflow (simulated trajectory from the logged n), and which beliefs would leave
(tier/branch/source mix — the collateral risk).

Phase B (separate go-ahead, only after the warrant re-validation is done):
NEX5_SELF_MAINTAIN=1 — the same controller actually sets paused=1, records every
pause in its own ledger, and when A < S unpauses ONLY ledger entries (newest first).
It never touches locked, protected, or harmonizer-paused beliefs; it never deletes;
it never unpauses anything it did not pause. Evaluated by section 4.

NOT TOUCHED by either phase: ingestion dedup, scheduler, writer code (used, not
modified), retrieval code and fountain_retrieval_log, the negative-feedback trio
(operator-defined; the operator should confirm the regulator does not overlap it),
warrant recorders.


7. HONEST LIMITS
----------------
- The setpoint follows her own 7-day history, so the level is held relative to her
  recent self (allostasis), not to an absolute number.
- P1/P2 passing partly follows from building a controller. What the evaluation adds
  is whether it holds under real inflow without breaching the guards.
- A pass is a measurable machine property. It does not make NEX self-aware, sentient
  or enlightened; nothing can verify that.
