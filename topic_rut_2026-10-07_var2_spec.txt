2. FIX — ONE VARIABLE: NEX5_CARRY_TOPIC_GATE (default OFF), generator.py only
----------------------------------------------------------------------------
Extend the recent-striking block's existing groove filter with a TOPIC-concentration
drop, parallel to how the phrase filter already drops grooved fires:
  - Detector (pure, testable): _dominant_topic_terms(thoughts, df_frac=0.40) tokenises
    each recent fire thought with the crystallizer's _fidelity_tokens and returns the
    content tokens whose DOCUMENT-FREQUENCY fraction across the recent-fire window is
    >= df_frac (a token in >= 40% of recent fires). Reuses _fidelity_tokens (lowercase,
    no stem — substring-matches raw text) and the existing in-code "dominates >= 40% of
    recent fires" convention (RUT_EDGE / register-warning). Window = last 40 fires
    (matches _stale_cluster_tokens' LIMIT 40).
  - Gate: in _build_recent_striking_block, when NEX5_CARRY_TOPIC_GATE=1, read the last 40
    fire thoughts (self._dynamic_reader) and drop from the deduped candidate POOL
    (_kept_rows) BEFORE the 2-sample any fire whose text contains a dominant topic term.
    Never empties the pool (if ALL kept fires are on the rut topic, keep them — the block
    stays a counterweight, fail-safe to current behaviour). The pre-sample placement
    means non-rut STRIKING fires still get surfaced instead of the block going empty.
  - Everything else unchanged: the existing phrase/template groove filter (runs after,
    exactly as today), the dedup, the sampling, the header, the 280-char clamp.
Flag OFF => byte-identical: the topic drop is the only new code and runs only under the
flag; _dominant_topic_terms is never called. The pre-existing recent-striking / retrieval
tests must stay green.

df_frac = 0.40 and window = 40 are PRE-REGISTERED from existing conventions, NOT tuned to
the Optimism rut (anti-tuning). See below.
